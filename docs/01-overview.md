# 01 · Overview

## Problem statement

Reduce engineering time spent on report consolidation and analysis by automating RTLA reporting, milestone reviews, and design-insight generation — while surfacing real design issues (power, clock-gating, coverage) that today require manual expert review.

## Who is this for?

- **RTL designers** who own power/area/clock-gating quality.
- **Verification engineers** tracking coverage and QoR across runs.
- **Design leads / architects** who consume milestone reviews and need trends, not raw dumps.

## The pain, quantified

| Task today | Typical effort / milestone | With RTLA AI Assistant |
|------------|----------------------------|------------------------|
| Consolidate RTLA reports → Excel | 2–4 hrs | < 2 min |
| Build milestone review PPTX | 2–3 hrs | < 5 min |
| Spot regressions across runs | manual, easy to miss | automated diff + root cause |
| Find missing clock gates | deep manual review | flagged with RTL line pointer |

> Replace the placeholder numbers above with your team's real measured baseline before the demo — measured numbers win.

## Value proposition (one line)

> A design-intelligence copilot that **finds power/clock-gating issues and saves N hours per milestone**, turning RTLA dumps into decisions.

## Challenge alignment

- **Reimagine the Future of Work** — removes repetitive report/deck toil so engineers focus on hard design problems.
- **Hack for Responsible AI** — grounded, cited, human-in-the-loop; numbers come from code, not the model. See [`05-responsible-ai.md`](05-responsible-ai.md).

## Success metrics

1. **Time saved** per milestone (hrs → min).
2. **Issues surfaced** the team would otherwise have missed (e.g., N missing clock gates).
3. **Trust**: % of agent insights with a verifiable source citation (target: 100%).
4. **Adoption**: number of engineers / runs processed.
